# ITS-SLI: SLA & SLI Engine for Zabbix

Панель мониторинга и расчета уровня обслуживания (SLA/SLI) серверов клиентов на основе событий и триггеров Zabbix Server. Разработана для ИТ-аутсорсинговых компаний и технических отделов для прозрачной оценки качества услуг, контроля доступности инфраструктуры, скорости реакции (MTTD) и решения проблем (MTTR).

---

## Ключевые возможности

* **Автоматическое сопоставление серверов по клиентам**:
  * Классификация по имени виртуальной машины (префиксу хоста) с отсечением служебных суффиксов (`1c`, `bkp`, `backup`, `nas`, `srv`, `sql`, `db`, `term`, `rdp` и др.).
  * Возможность ручного переопределения клиента, закрепления за кастомными клиентами и добавления комментариев.
* **Математически точный расчет SLA без наложения простоев**:
  * **Объединение пересекающихся сбоев (Interval Merging)**: Если во время аварии на сервере одновременно сработало несколько триггеров Zabbix (например, потеря связи, недоступность агента и сбой службы), интервалы объединяются. Время простоя не умножается, предотвращая ложный обвал SLA.
  * **Учет рабочего времени (Business Hours)**: Расчет доступности только в согласованные рабочие часы (например, с 09:00 до 18:00 по будням). Инциденты в нерабочее время исключаются из SLA.
  * **Фильтрация кратковременных сбоев сети/VPN**: Автоматическое или ручное исключение кратковременных инцидентов (ниже настраиваемого порога секунд).
  * **Регламентные работы (Maintenance)**: Автоматическое определение флага подавления обслуживанием (`suppressed`) непосредственно из событий Zabbix.
  * **Глобальные правила исключения**: Создание правил по подстрокам для исключения некритичных триггеров из расчета SLA всего парка.
* **Авторизация через Active Directory / LDAP и локальные пользователи**:
  * Поддержка входа по корпоративной почте (`user@company.local`), доменному логину (`DOMAIN\user`) или короткому имени (`user`).
  * Разграничение прав по группам безопасности Active Directory (с рекурсивной проверкой вложенных групп `LDAP_NESTED_GROUPS`).
  * Автоматическое создание учетной записи в локальной БД при первом входе (JIT Provisioning).
  * Резервный локальный вход (Break-Glass fallback): локальный администратор доступен даже при недоступности контроллеров домена.
* **Безопасность и отказоустойчивость**:
  * Разграничение доступа по ролям (RBAC): настройки, синхронизация, рассылка отчетов и управление пользователями защищены ролью администратора.
  * Защита от перебора паролей (Rate Limiting) в базе данных с корректным учетом `X-Forwarded-For` за Reverse Proxy.
  * Защита от XSS (экранирование HTML-вывода данных инцидентов и серверов).
* **Метрики эффективности технического отдела**:
  * **MTTD (Mean Time to Detect)**: Время от возникновения сбоя до подтверждения (Acknowledge) дежурным инженером в Zabbix.
  * **MTTR (Mean Time to Resolution)**: Время от возникновения сбоя до восстановления сервиса.
* **BI-аналитика инцидентов**:
  * Группировка проблем по типам («Диски», «Сеть», «Службы 1С» и др.) на основе настраиваемых паттернов.
  * Интерактивные графики распределения, подсчет суммарного простоя и топ клиентов по каждой проблеме.
* **ТВ-панель (NOC-дашборд)**:
  * Полноэкранный интерфейс `/tv` для вывода на настенные экраны с автообновлением без перезагрузки страницы.
  * Безопасный доступ по отдельному токену без ввода логина и пароля на ТВ.
* **Отчетность и экспорт**:
  * Отправка детализированных Excel-отчетов на почту (SMTP / SMTPS SSL) и сводок в Telegram.
  * Автоматическая еженедельная и ежемесячная рассылка по расписанию списку адресатов (`REPORT_RECIPIENTS`).
  * Адаптивная печатная версия страниц для чистого экспорта в PDF через браузер.

## Быстрый запуск в Docker

Контейнер автоматически собирается через GitHub Actions и публикуется в GitHub Packages (GHCR).

### 1. Клонирование репозитория
```bash
sudo git clone https://github.com/Ttolyanich/zabbix-sli.git /opt/zabbix-sli
cd /opt/zabbix-sli
```

### 2. Настройка файла окружения `.env`
Создайте `.env` из примера:
```bash
sudo cp .env.example .env
sudo nano .env
```

Пример базовой конфигурации:
```ini
# Порт и IP привязки
BIND_PORT=5005
BIND_IP=127.0.0.1
DATABASE_PATH=./data/sli_dashboard.db

# Секретный ключ Flask (при отсутствии сгенерируется автоматически в data/.secret_key)
SECRET_KEY=your_secure_secret_key_here

# ----------------------------------------------------
# Настройки Active Directory / LDAP (опционально)
# ----------------------------------------------------
LDAP_ENABLED=true
LDAP_SERVER=ldap://dc01.company.local
LDAP_PORT=389
LDAP_USE_SSL=false
LDAP_DOMAIN=company.local
LDAP_BASE_DN=DC=company,DC=local
LDAP_BIND_USER=svc_zabbix_sli
LDAP_BIND_PASSWORD=YourServicePassword
LDAP_REQUIRED_GROUP=SLA-Monitoring-Users
LDAP_ADMIN_GROUP=Domain Admins
LDAP_ADMIN_USERS=admin,sysadmin
LDAP_NESTED_GROUPS=true
```

### 3. Запуск контейнера
```bash
sudo docker compose up -d
```

Панель станет доступна по адресу: `http://<IP_СЕРВЕРА>:5005`.

## Первый вход и настройка

1. Откройте панель в браузере.
2. Войдите под учетной записью локального администратора по умолчанию:
   * **Логин**: `admin`
   * **Пароль**: `admin`
   *(Если включен LDAP, также доступен вход под доменными учетными записями)*.
3. При входе с дефолтным паролем перейдите в **«Настройки»** и смените пароль в блоке **«Смена пароля»**.
4. В разделе **«Интеграция с Zabbix»** укажите:
   * URL API Zabbix (например, `https://zabbix.company.local`);
   * API-токен или связку логин/пароль;
   * Нажмите «Проверить подключение» и «Сохранить настройки».
5. Нажмите кнопку **«Синхронизировать»** в сайдбаре для первой выгрузки хостов и инцидентов.

## Настройки интеграций и параметров

| Переменная | Описание | По умолчанию |
| :--- | :--- | :--- |
| `BIND_PORT` | Порт приложения | `5005` |
| `BIND_IP` | IP-адрес для прослушивания контейнером | `127.0.0.1` |
| `DATABASE_PATH` | Путь к файлу базы данных SQLite | `./data/sli_dashboard.db` |
| `SECRET_KEY` | Ключ шифрования сессий Flask | Автогенерация |
| `LDAP_ENABLED` | Включение авторизации через домен AD/LDAP | `false` |
| `LDAP_SERVER` | Адрес контроллера домена (`ldap://` или `ldaps://`) | — |
| `LDAP_PORT` | Порт LDAP (389 для LDAP, 636 для LDAPS) | `389` |
| `LDAP_USE_SSL` | Использовать SSL/TLS шифрование | `false` |
| `LDAP_DOMAIN` | Имя домена компании (например, `domain.local`) | — |
| `LDAP_BASE_DN` | Базовый DN каталога для поиска (`DC=domain,DC=local`) | — |
| `LDAP_BIND_USER` | Сервисный аккаунт для первичного поиска пользователей | — |
| `LDAP_BIND_PASSWORD` | Пароль сервисного аккаунта | — |
| `LDAP_REQUIRED_GROUP` | Имя группы AD, обязательной для доступа | — |
| `LDAP_ADMIN_GROUP` | Группа AD, членам которой выдаются права администратора | `Domain Admins` |
| `LDAP_ADMIN_USERS` | Список логинов через запятую с правами администратора | `admin,sysadmin` |
| `LDAP_NESTED_GROUPS` | Проверка рекурсивного членства во вложенных группах AD | `true` |

Параметры Zabbix, SMTP, Telegram, рабочего времени и порога VPN настраиваются администратором через веб-интерфейс (вкладка **«Настройки»**).

## Архитектура проекта

```
zabbix-sli/
├── app.py                  # Маршруты Flask, сессии, контроль прав RBAC, REST API
├── auth_ldap.py            # Модуль интеграции с Active Directory / LDAP (ldap3)
├── database.py             # Работа с SQLite, схемы таблиц, персистентный rate-limiting
├── analytics.py            # Математический расчет SLA/SLI, объединение сбоев (Interval Merging)
├── scheduler.py            # Фоновый планировщик APScheduler (синхронизация Zabbix, отчеты)
├── zabbix_api.py           # Взаимодействие с Zabbix JSON-RPC API, учет suppressed maintenance
├── notifier.py             # Генератор отчетов в Excel (openpyxl), SMTP/SSL рассылка, Telegram
├── static/                 # Фронтенд (app.js со встроенной защитой от XSS, стили CSS)
├── templates/              # HTML-шаблоны Jinja2 (index.html, login.html, tv.html)
├── Dockerfile              # Сборка контейнера на Python 3.11-slim
└── docker-compose.yml      # Декларативное развертывание сервиса
```
