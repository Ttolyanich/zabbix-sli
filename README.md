# ITS-SLI: SLA & SLI Engine for Zabbix

Панель мониторинга и расчета уровня обслуживания (SLA/SLI) серверов клиентов на основе событий и триггеров Zabbix Server. Разработана для ИТ-аутсорсинговых компаний для оценки качества работы технического отдела, скорости реакции (MTTD) и решения проблем (MTTR).

---

## Основные возможности

* **Автоматическое распределение серверов по клиентам**:
  * Классификация по имени виртуальной машины (префиксу хоста) с автоматическим отсечением технических окончаний (`1c`, `bkp`, `backup`, `nas`, `srv`, `sql`, `db`, `term`, `rdp` и др.).
  * Возможность ручного переопределения привязки сервера к клиенту и добавления комментариев по серверам.
* **Расширенные параметры расчета SLA**:
  * **Учет рабочего времени (Business Hours)**: Возможность расчета доступности серверов только в рабочее время (например, с 09:00 до 18:00 по будням). Сбои во внерабочее время не влияют на SLA.
  * **Исключение сетевых сбоев**: Автоматическое или ручное исключение кратковременных инцидентов (менее 1 минуты), связанных со сбоями сети или VPN.
  * **Учет обслуживания (Maintenance)**: Полное исключение простоев во время регламентных работ, настроенных в Zabbix.
* **Метрики эффективности отдела**:
  * **MTTD (Mean Time to Detect / Реакция)**: Время от возникновения сбоя до подтверждения (Acknowledge) дежурным инженером в Zabbix.
  * **MTTR (Mean Time to Resolution / Решение)**: Время от возникновения сбоя до полного восстановления работоспособности.
* **Документирование инцидентов**:
  * Возможность оставлять текстовые комментарии (описание причин сбоя/проделанных работ) и менять категории сбоев прямо на дашборде.
* **ТВ-панель (NOC-дашборд)**:
  * Отдельная страница `/tv` для вывода на телевизор: общая доступность серверов, топ проблемных хостов по суммарному простою (с подписью клиента), список проблемных клиентов.
  * Автообновление данных без перезагрузки страницы, подсветка хостов с активными проблемами.
  * Доступ по токену без входа в систему (токен — на вкладке «Настройки», карточка «ТВ-панель»).
  * Параметры URL: `?period=today|7d|30d|month` — период расчета, `?refresh=60` — интервал обновления в секундах, `?top=20` — размер топа.
* **BI-аналитика по типам проблем**:
  * Администратор создает произвольные группы проблем (например, «Проблемы с диском», «Сетевые сбои») и привязывает к ним паттерны — подстроки, по которым инциденты автоматически классифицируются (вкладка «Настройка аналитики»).
  * Диаграмма распределения проблем по группам на главном дашборде.
  * Отдельная вкладка «Аналитика» (доступна всем пользователям) с полным отчетом: количество и доля инцидентов по каждой группе, суммарный простой, топ клиентов, у которых проблема встречается чаще всего.
* **Отчетность и экспорт**:
  * Ручная отправка подробных Excel-отчетов на Email и сводок в Telegram.
  * Автоматическая еженедельная и ежемесячная рассылка отчетов.
  * Адаптивная печатная версия страниц для экспорта отчета в PDF через браузер.

## Быстрый запуск в Docker

Для развертывания проекта выполните следующие шаги на целевом сервере:

### 1. Клонирование репозитория
Сделайте клон репозитория в каталог `/opt/zabbix-sli`:
```bash
sudo git clone https://github.com/Ttolyanich/zabbix-sli.git /opt/zabbix-sli
cd /opt/zabbix-sli
```

### 2. Настройка окружения
Создайте файл `.env` на основе примера и настройте параметры (порт и др.):
```bash
sudo cp .env.example .env
sudo nano .env
```

Параметры по умолчанию в `.env`:
```ini
BIND_PORT=5005
SECRET_KEY=generate_your_secure_secret_key_here
```

> `SECRET_KEY` можно не задавать — при отсутствии переменной ключ генерируется автоматически и сохраняется в `data/.secret_key`.

### 3. Запуск контейнеров
Запустите приложение в фоновом режиме. Контейнер автоматически скачает готовый образ с GitHub Packages (GHCR):
```bash
sudo docker compose up -d
```

Приложение станет доступно по адресу: `http://<IP_СЕРВЕРА>:<BIND_PORT>` (по умолчанию `http://localhost:5005`).

## Первый вход и авторизация

1. Откройте панель в браузере.
2. Введите учетные данные администратора по умолчанию:
   * **Логин**: `admin`
   * **Пароль**: `admin`
3. При первом входе система выдаст предупреждение и потребует изменить дефолтный пароль. Перейдите на вкладку **«Настройки»** и установите надежный пароль в форме **«Смена пароля»**.
4. На вкладке **«Пользователи»** вы сможете создать дополнительные учетные записи для сотрудников (роли `admin` или `user`).

## Архитектура проекта

* **Backend**: Python / Flask, SQLite (локальный кэш событий и настроек интеграции).
* **Frontend**: HTML5, Vanilla CSS, JS (Chart.js для визуализации, FontAwesome для иконок).
* **Синхронизация**: Раз в 10 минут фоновый планировщик `APScheduler` запрашивает последние события Zabbix Server API по пакетам и обновляет метрики.
